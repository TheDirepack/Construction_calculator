# Tools for PDF plan measuring

Construction Calc supports Android API 26. The first prototype can use Android's renderer and the Compose stack already in the app. The PDF writer needs to preserve the source pages and add visible markups. Editable data travels in standalone JSON or the project ZIP. [App SDK levels](../../build-logic/convention/src/main/kotlin/ProjectExtensions.kt) · [PDF plan measuring proposal](../plans/pdf-plan-measuring.md)

## Built-ins and existing app code

| Job | First choice |
|---|---|
| Open and save files | Reuse the Storage Access Framework entry points in `DataTransfer` and the sharing pattern in `ProjectSharing`. Stream an imported URI to an app-managed file and hash the source as it is copied. The local file gives the renderer the seekable descriptor it requires. [DataTransfer](../../core/ui/src/main/kotlin/com/thedirepack/constructioncalc/core/ui/components/DataTransfer.kt) · [ProjectSharing](../../core/data/src/main/kotlin/com/thedirepack/constructioncalc/core/data/ProjectSharing.kt) · [PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer) |
| Render a sheet | Use `PdfRenderer.Page.render` with a matrix and destination clip for visible tiles. It is available across our API range. Serialize rendering per document, run it off the UI thread, and bound the bitmap cache. Evaluate an isolated process for parsing imported PDFs, as Android recommends. [Rendering API](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page) · [PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer) |
| Interact with plans | Use Compose Canvas and pointer gestures. Share a forward and inverse transform between page display, touch hit testing, and the overlay. Test 90° rotations and sheets whose crop box starts away from the page origin. Check what geometry each PDF adapter exposes before fixing the conversion to native PDF annotation coordinates. [Compose multitouch](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/multi-touch) |
| Calculate and save | Use pure Kotlin for distance, polyline length, polygon area and count. Reuse `core:measure` for quantities, `ResultValue` for the picker, and `Project.withRunPath` for a reviewed route. [Existing integration](../ARCHITECTURE.md#how-the-pieces-connect) |
| Export JSON and ZIP | Reuse kotlinx.serialization and the project codec. Start with Android's `java.util.zip` streams. Generate entry paths from revision IDs, validate the manifest and actual extracted sizes, and stage files before saving the project. [ProjectCodec](../../core/model/src/main/kotlin/com/thedirepack/constructioncalc/core/model/ProjectCodec.kt) · [Android ZIP streams](https://developer.android.com/reference/java/util/zip/package-summary) |
| Generate a report | Keep using Android's `PdfDocument` for reports like panel schedules. Its canvas API creates new pages. The plan exporter needs to edit a copy of an existing document. [PanelPdf](../../feature/panels/src/main/kotlin/com/thedirepack/constructioncalc/feature/panels/PanelPdf.kt) · [PdfDocument](https://developer.android.com/reference/android/graphics/pdf/PdfDocument) |

## Viewer and writer candidates

| Candidate | Where it fits | What to check |
|---|---|---|
| AndroidX PDF | Candidate for search, text selection, accessibility and ready-made navigation. Google lists `1.0.0-beta01` and a read/render backport to API 28. [AndroidX PDF releases](https://developer.android.com/jetpack/androidx/releases/pdf) | Keep framework rendering for API 26–27. Before adopting the viewer, check that custom overlays can reliably map touches and positions to pages and that the needed features work on no-GMS devices. |
| PdfBox-Android | A quick Android writer prototype. Check the port's annotation appearance, page box and rotation APIs. [Port releases](https://github.com/TomRoush/PdfBox-Android/releases) · [Apache PDFBox examples](https://github.com/apache/pdfbox/tree/trunk/examples/src/main/java/org/apache/pdfbox/examples/pdmodel) | The latest published port shown upstream is based on PDFBox 2.0.27. Use controlled fixtures first. Establish a maintained release or patch path and check transitive dependencies. [Apache PDFBox advisories](https://pdfbox.apache.org/security.html) |
| PDFium through an Android binding | Open-source writer alternative if the PDFBox port has no viable maintenance path. Upstream exposes APIs for annotations and saving a copy. KotlinPdfium is a reference for Android bindings. [Annotation API](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_annot.h) · [Save API](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_save.h) · [KotlinPdfium](https://github.com/HyntixDev/KotlinPdfium) | KotlinPdfium is AGPL-3.0 and advertises arm64 only. Verify annotation appearances and save support before choosing any binding. A direct JNI route would also need API 26, x86_64 emulator and release ABI checks, native updates, APK size checks, and 16 KB compatibility. [Android 16 KB support](https://developer.android.com/guide/practices/page-sizes) |
| iText Android and OpenPDF | iText has an Android SDK. OpenPDF is another Java writer candidate. [iText Android](https://kb.itextpdf.com/itext/installing-itext-on-android) · [OpenPDF](https://github.com/LibrePDF/OpenPDF) | iText has AGPL and commercial licensing options. OpenPDF needs a build and runtime check on API 26 before it makes the shortlist. [iText licensing](https://www.itextpdf.com/how-buy) · [OpenPDF Android issue](https://github.com/LibrePDF/OpenPDF/issues/1512) |

## What Jetpack PDF can cover

- **Viewer and overlays.** The beta exposes `PdfView.viewToPdfPoint` and `pdfToViewPoint`. The Compose `PdfViewerState` has `visibleOffsetToPdfPoint` and `pdfPointToVisibleOffset`, plus visible page and zoom state. That gives us a direct way to prototype taps and a live measurement overlay. The Compose viewer and its state still require experimental opt-in. Jetpack's `PdfPoint` uses a page-local top-left origin. Test crop offsets and PDF rotation before mapping those points to our stored coordinates or to a writer. [PdfView](https://developer.android.com/reference/androidx/pdf/view/PdfView) · [PdfViewerState](https://developer.android.com/reference/kotlin/androidx/pdf/compose/PdfViewerState) · [PDF model reference](https://developer.android.com/reference/androidx/pdf/package-summary) · [Beta release notes](https://developer.android.com/jetpack/androidx/releases/pdf)
- **Headless rendering and text.** `SandboxedPdfLoader` opens PDFs through a sandboxed service. The resulting `PdfDocument` exposes page metadata, bitmap sources, native text and search. This lets us evaluate Jetpack for document loading or text search while retaining our own measurement UI. Native text and vector line snapping are separate capabilities. The public page-content API returns text and images, so general CAD-path snapping still needs a source of vector paths. [SandboxedPdfLoader](https://developer.android.com/reference/kotlin/androidx/pdf/SandboxedPdfLoader) · [PdfDocument](https://developer.android.com/reference/kotlin/androidx/pdf/PdfDocument)
- **Editing and export.** `EditablePdfDocument` can apply an `EditsDraft` and create a write handle for saving. This is a candidate for the annotated PDF export on supported devices. Test whether it can write the required lines and labels with appearances that other readers display, and check runtime support for those edits separately from ordinary viewing. [EditablePdfDocument](https://developer.android.com/reference/kotlin/androidx/pdf/EditablePdfDocument)

Compare a standalone API 28+ Jetpack prototype with the API 26 framework viewer on the same rotated, cropped sheet. Check overlay drift during a fling and pinch, gesture conflicts between editing and navigation, and basic rendering on AOSP. Check the chosen AAR manifests and runtime SDK extension requirements before integrating Jetpack into a build that supports API 26. Android's manifest merger checks a dependency's minimum at build time. [Manifest merger](https://developer.android.com/build/manage-manifests)

## What FieldScale does on Android

Static inspection of the supplied FieldScale 3.5.6 XAPK confirmed framework `PdfRenderer` calls for full-page and clipped tile rendering through a Flutter platform channel. Its manifest declares API 24 as the minimum. The PDF writer is PdfBox-Android. The native code uses a named optional-content layer and standard annotations for visible marks. It also writes and reads a versioned JSON attachment through the embedded-files index. Construction Calc's planned editable exports use standalone JSON and the project ZIP. No APK was installed or run. [FieldScale rendering and export notes](fieldscale.md#65-rendering)

## Desktop check already completed

A scratch test used pypdf 6.20.1 to write a copy of a two-page fixture with a rotated, offset-crop page. It added a line annotation with a stable ID and embedded `drawing.json`. Poppler's `pdfdetach` returned the exact JSON bytes. Its `pdftoppm` showed the markup when annotations were enabled and matched the original page render when they were hidden. Reopening the file preserved the page rotation, crop box, and selectable text. The original file's SHA-256 stayed the same. This verifies the file design in one desktop reader. [pypdf writer API](https://pypdf.readthedocs.io/en/stable/modules/PdfWriter.html) · [Poppler](https://poppler.freedesktop.org/)

## First Android prototypes

1. **Viewer and geometry.** Measure the same known line before and after a pan, zoom, and rotation on API 26 and a current AOSP device. Include a nonzero crop origin and a large scanned sheet. Record peak bitmap memory and check that a saved measure appears in the value picker.
2. **Writer.** Export one line and label on the rotated test page. Try Jetpack's edit and save APIs on a supported device and compare with a writer that can cover API 26. Use Poppler as an independent check of visible markups and preservation of existing text and annotations. Separately reopen the standalone JSON with its matching original PDF and restore one editable markup.
3. **Project archive.** Round-trip two same-named drawings with independent scales, a saved run link and the original PDF bytes. Exercise both an older project JSON file and a ZIP with a missing drawing. Confirm a failed import creates no partial project.

Keep desktop fixture tools out of app dependencies. Add a writer to the app only after the Android prototype passes and its maintenance path is clear.
